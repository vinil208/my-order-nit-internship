# Thirty technical interview questions

1. **What problem does My Order solve?** It connects a small food factory's mobile orders, recipe consumption, actual production, stock, GST invoices and collections, keeping source references for audit.
2. **What is distinctive about it?** A shortage can be followed through a deterministic production recommendation, material requirements, actual costing and dispatch. Financial credit and physical return are deliberately separate. These are practical design strengths, not a claim of a world-first invention.
3. **Why Node and SQLite?** Node 24 provides HTTP, crypto and SQLite without runtime dependencies. The student can run and explain one process and one transactional database.
4. **Where is the write boundary?** Factory.act wraps a validated command, source records, movements, audit and request response in BEGIN IMMEDIATE. Any exception rolls everything back.
5. **How do simultaneous approvals avoid overselling?** SQLite permits one writer at a time. The second approval reads committed reservations before deciding. A worker-thread test uses independent connections with a shared start gate.
6. **What is a reservation?** The quantity on approved or invoiced order lines that has not been dispatched or cancelled. It is derived inside the transaction rather than maintained as a second stock balance.
7. **When is physical stock reduced?** Only dispatch posts the sales issue. Approval reserves; invoice posting records money and leaves physical stock unchanged.
8. **What happens on cancellation?** Submitted/approved orders are cancelled with a reason. Invoiced orders use a retained credit. Reservation release is audited.
9. **How does partial fulfillment work?** Strict approval is the default. When split is configured and selected, available quantity is approved and a linked submitted order preserves the remainder. This is not partial dispatch of an invoice.
10. **How are retries safe?** A user/key primary key stores the original result and a canonical action/payload hash. Identical retries return that result; changed requests using the key return 409.
11. **How is money represented?** Integer paisa, with BigInt intermediate multiplication and half-up rounding. Quantities use integer thousandths. Display percentages are not posted monetary arithmetic.
12. **Why moving weighted average?** Interchangeable materials in a small factory can share a meaningful average acquisition cost without tracking each supplier lot. The method and its lack of lot-level provenance are documented.
13. **Explain the benchmark flour cost.** Opening 100 kg at 42 plus purchase 60 kg at 45 gives 6900 rupees over 160 kg, or 43.125/kg. Consuming 40 kg costs 1725.
14. **Explain INR 31.14.** Actual materials/packaging total 4055; labour 1200 and utilities 600 produce 5855. Divide by 188 good packets:31.143617..., rounded 31.14.
15. **How is damaged packaging treated?** The 194 consumed pouches include 188 good and 6 damaged. All 485 rupees of pouch cost is already in the run. The damaged-cost disclosure is not added again.
16. **What if output is zero?** An explicit failure reason is required. Materials remain consumed, the cost is reported as failed-run cost, and no finished inventory value is created. Division by zero is avoided.
17. **How are recipe changes handled?** New recipes create new BOM rows. Runs snapshot planned/actual components. Approved schedules retain their selected BOM ID; new recommendations use the newest active version.
18. **How does the planner avoid counting demand twice?** It considers submitted demand against free stock, adds any deficit in already-reserved eligible stock, and subtracts scheduled output. It does not subtract an approved order from both demand and free stock.
19. **How is the batch recommendation calculated?** Ceiling of shortage divided by BOM yield. The benchmark shortage 32 and yield 200 recommends one batch. No LLM is involved.
20. **Does a schedule reserve raw materials?** No. It reduces planning availability for other recommendations, but posting must revalidate actual stock. This distinction avoids presenting an estimate as a guaranteed reservation.
21. **How are expiry and FEFO enforced?** Only dated, non-expired, manufactured finished batches are eligible. Dispatch selects earliest expiry and records invoice/batch allocations. Expiry can make an existing reservation unfulfillable; posting rechecks it.
22. **What does recall traceability cover?** Finished batch, associated run/BOM, actual consumed material quantities, dispatch invoices and affected customers. Historical supplier material lot identities were not recorded and cannot be inferred.
23. **Why separate credit, return and refund?** A credit reduces the financial claim, a return proves goods physically came back, and a refund moves collected money out. Combining them would invent stock or cash movements. Returned food enters quarantine.
24. **What does reconciliation compare?** Source-document quantities against ledger movements; source receipt values; finished batch totals; invoice arithmetic; and payment/refund limits. Missing/duplicate references and negative balances are exceptions requiring investigation.
25. **What prevents silent stock correction?** No balance-edit API exists. Movements are append-only and database triggers reject edits/deletions. Adjustments require source reasons and reversals reference one original document.
26. **How does offline sync work?** The salesman shell and masters are cached. Drafts persist locally with client IDs and statuses. On reconnect the server validates customer permissions, current price and the original request key. Stock is reserved only later at approval.
27. **What if the price changed offline?** The expected cached price differs from the current master and causes 409 before posting. The user reviews current prices or discards the draft. Unknown network outcomes must be retried with the same key or checked in the order book.
28. **How are permissions enforced?** The API checks the authenticated user; every write explicitly lists permitted roles. State is scoped for salesmen and production. Auditor/owner are read-only and accountant has narrowly defined financial commands.
29. **Which evidence would you show?** npm test, npm run benchmark, the multi-connection/rollback/migration tests, browser offline demo, source-linked reports and meaningful Git commits. Test output is recorded rather than inferred from code.
30. **What would you improve before real use?** Non-demo identity management, HTTPS, backup/restore drills, monitoring, period locks, supplier-lot capture, capacity planning, partial returns, Unicode PDFs and larger-volume performance work. This version is an operational prototype, not full statutory accounting software.
